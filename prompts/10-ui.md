# CODEX TASK 10 — Finance analyst workstation

Read project spec and existing backend API. No mocked success states when API is present.

## Goal
Deliver a coherent local Next.js UI with four functioning views and a complete CASE-204 demo through actual backend endpoints.

## Implement
1. Cash Inbox — import status, receipts, suspected duplicates, unapplied vs applied amounts, customer candidate match options, error handling.
2. Case Workbench — claims independently, citations opening original evidence, investigation progress, events, next recommended action, approve/request evidence.
3. Posting/Approval Queue — account lines, debits/credits, balance check, source/version staleness, role permissions and journal simulator controls.
4. Recovery/Audit — open/disputed cases, age, unresolved amounts, timelines and event replay; simple real backend-derived analytics.
5. Responsive layout, accessible keyboard interactions, loading/empty/failure states. Enforce backend authorization regardless of UI visibility.
6. E2E demo path: seed/import -> receipt -> remittance -> damage evidence investigation -> journal proposal -> controller action -> simulate post -> open residual and draft evidence request -> attach new evidence -> reinvestigate.

## Tests
Frontend checks (lint/typecheck/build), Playwright critical path(s), API error and duplicate submission behavior. Seed data and run commands documented.

## Non-goals
No marketing landing page, dashboards with fabricated metrics, external bank/payment email integration. Update status. STOP.
